# Расчёт грузов по осадке → Python (по книгам и кодексу ООН)

Цель: восстановить алгоритмы из технических источников (формулы, таблицы,
примеры survey, формы A–E, программа BASIC кодекса ООН) и перенести их в
небольшие Python-модули, доказав тестами на контрольных примерах, что
Python считает так же, как первоисточник.

## Как передать мне книги (если в чате нет кнопки загрузки файлов)

Рабочий порядок вариантов — от самого надёжного к запасному:

1. **Git-репозиторий (рекомендуемый способ).** Этот workspace — обычный git-
   репозиторий. Заведи приватный репозиторий на GitHub/GitLab (или локально
   на флешке), залей туда сканы/PDF/BASIC, и я подтяну их командой
   `git pull` / клонированием в `sources/originals/`. Оригиналы при этом
   остаются версифицированными — это соответствует нашему принципу
   «только первоисточники» и даёт нам хэши для карточек спецификаций.
2. **Облачная ссылка.** Выложи файлы в любое хранилище с прямой ссылкой
   (Google Drive/Dropbox/S3/HTTP) и пришли ссылку в чат — я скачаю через
   `curl/wget` прямо в `sources/originals/`. Важно: ссылка должна отдавать
   сам файл, а не страницу предпросмотра.
3. **Базовая кодировка в чат.** Для небольших файлов (страницы сканов,
   блоки BASIC) можно вставить base64 прямо в сообщение; я декодирую в
   файл. Команда на твоей стороне: `base64 -i page.png > page.b64`, затем
   вставь содержимое. Это коряво, но работает без всякого upload.
4. **Живой текст.** Формулы и программу BASIC проще всего прислать
   обычным текстом в сообщении — для кода это даже надёжнее OCR: не теряются
   индексы, знаки и цифры. Скан страницы всё равно желательно приложить
   позже способом 1 или 2 как доказательство источника.

Чего делать НЕ надо: пересылать только старые OCR-переводы — именно в них
чаще всего искажены таблицы поправок и десятичные точки.

Ключевой принцип из твоего плана: работаем по **оригинальным страницам**,
а не по предыдущим OCR-переводам. Поэтому рядом с каждым распознанным
фрагментом сохраняем ссылку на источник (страница).

## Структура репозитория

```
sources/originals/   # оригиналы книг/сканов/файлов BASIC (как получены)
specs/               # спецификации: формула, переменные, единицы, порядок вычислений
src/                 # Python-модули (по одному подтверждённому алгоритму на модуль)
tests/               # pytest: сверка с числовыми примерами из книг
examples/            # входные данные контрольных примеров + ожидаемые результаты
```

## Конвейер работы (три задачи из плана)

### 1. Изучение источников
Для каждого фрагмента создаём карточку в `specs/NNN_имя.md`:

- Источник: книга, страница, файл оригинала (хэш/ссылка).
- Формула в исходной записи (как в книге) и в переписанном виде без изменения смысла.
- Таблица переменных: символ, смысл, единица, диапазон/допущения.
- Порядок вычислений шаг за шагом (нумерованный, с указанием знаков поправок).
- Контрольный пример из книги: данные → промежуточные значения → итог.
- Особые случаи и неоднозначности (что трактуют сами, что надо уточнить).

Правило: **пока карточка не сверена с оригиналом постранично, код не пишем.**

### 2. Разработка
- Один алгоритм = один небольшой модуль в `src/`, чистые функции,
  явные единицы, никаких «магических» констант без ссылки на таблицу источника.
- Константы из таблиц (гидростатика, поправки) — отдельными данными
  (CSV/YAML) с указанием страницы-источника.

### 3. Независимая проверка
- Каждый контрольный пример из книги становится тестом в `tests/`.
- Сравнение: точное совпадение там, где пример округлён до разряда;
  иначе — допуск, обоснованный разрядом исходных данных.
- Отдельный прогон «второй моделью» (Claude/Gemini) по спецификации +
  коду + тестам: искать пропущенные поправки, ошибки знаков, слабые тесты.

## Этап «экзамен модели» (из твоего сообщения)

Контрольный набор из четырёх типов материала:

| № | Тип материала | Где лежит | Статус |
|---|---------------|-----------|--------|
| 1 | Страница с формулой и пояснением переменных | sources/originals/ | ждёт загрузки |
| 2 | Таблица гидростатических характеристик / поправок | sources/originals/ | ждёт загрузки |
| 3 | Полный числовой пример расчёта survey | sources/originals/ | ждёт загрузки |
| 4 | Фрагмент/блок программы BASIC кодекса ООН | sources/originals/ | ждёт загрузки |

Каждой модели даём один и тот же фрагмент и просим:
1. переписать формулу без изменения смысла;
2. объяснить каждую переменную и единицу измерения;
3. восстановить последовательность вычислений;
4. выполнить числовой пример;
5. (наше дополнение) указать все места, где возможен ошибка знака/порядка,
   и перечислить неоднозначности, которые нельзя разрешить по фрагменту.

Оцениваем по сверке с оригиналом: точность распознавания цифр и индексов,
полнота списка поправок, воспроизводимость числа из примера.

## Правила безопасности работы (анти-потеря)

1. Каждая завершённая логическая единица (карточка, модуль, тест) — отдельный
   коммит сразу после проверки, не накапливаем изменения.
2. Коммиты пушим при первой возможности; если нет доступа к remote — коммитим
   локально и оставляем заметку здесь.
3. Чёрновые выводы всегда помечаем «ждёт сверки с оригиналом» — код, не
   подтверждённый страницей книги, не считается результатом.
